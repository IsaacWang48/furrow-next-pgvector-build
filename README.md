Run only after the repository owner approves this exact build job. ## Permissions, cost and limits

Job token permissions: contents:read for this public repository, id-token:write solely for GitHub provenance signing, attestations:write solely for that provenance. No repository contents write, packages write, deployment, cloud database credential, environment secret, cache or paid service. Checkout does not retain credentials. The build logs only allowlisted version/context fields, never a complete environment or token. Host tooling and the source remain public.

GitHub documents standard public runners as free and explicitly excludes workflow logs/job summaries from the owner's artifact storage allowance (https://docs.github.com/en/billing/concepts/product-billing/github-actions). Public artifact attestations are available on current Free/Pro/Team plans (https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations). Expected elapsed build/test time is 10-20 minutes, not a measured guarantee; workflow timeout is 30 minutes. Expected charge is USD0 on this standard public route, with zero artifact/cache/Packages/LFS/custom-image storage. Shared storage allowance is unknown and is never assumed sufficient. No paid fallback, larger runner, private execution, release or budget change is authorized. Log delivery is bounded to 10MiB of transport ZIP; overflow, redaction or truncation blocks delivery instead of switching storage. Preserve the downloaded logs/verified evidence before normal log expiry and retain the source repository/attestation provenance; stop Actions after the approved run. Do not delete provenance automatically.

This is a reproducible recipe with pinned source and development inputs, not a claim of bit-identical builds: windows-2022 image updates and MSVC default PE timestamps can change output hashes. Record exact image/tool versions and review actual outputs. The supported backend is specifically the locked EDB17.11 distribution, not arbitrary PG17 vendor builds. The remote synthetic database proves extension behavior only; it never establishes a populated application restore, migrations, hosted readiness, voice/UI acceptance or ticket closure.
